# Borrador operativo para el piloto observado

Preparado; no ejecutado ni validado por docentes/investigadores. Uso previsto: quinto/sexto, fracciones, hogar. No trasladar automáticamente la muestra por aulas del documento base.

## Antes de cada sesión

Responsable revisa las autorizaciones familiares y el asentimiento del participante conforme al protocolo aprobado. Asignar un código sin nombre ni fecha de nacimiento; guardar la correspondencia fuera de la telemetría. Registrar versión de aplicación, dispositivo, tamaño de pantalla, disponibilidad de sonido y condiciones de acompañamiento. Preparar una partida separada y exportar el registro al terminar. No reutilizar la partida personal del desarrollador.

## Secuencia propuesta

1. Presentar que puede pedir ayuda, descansar o terminar, sin premios condicionados a continuar.
2. Aplicar forma inicial externa, sin ayudas de Luma; registrar respuestas sin mostrar soluciones todavía.
3. Observar una sesión breve, fijando su duración con el equipo antes de comenzar. No introducir errores deliberados para provocar señales. Registrar cada intervención adulta.
4. Aplicar forma externa alternativa y una pregunta abierta sobre lo que resultó fácil/difícil. Solicitar explicación de dos respuestas, no solo aciertos.
5. Exportar JSON, anotar interrupciones y cotejar señales con observación. Si pide terminar o el responsable observa malestar, detener y conservar lo registrado sin convertir la salida en fracaso.
6. Agendar retención por separado, con un tercer conjunto de tareas revisado; no prometer medir ocho semanas de retención dentro de cuatro semanas de seguimiento.

## Plantilla de observación

| Campo | Valores / criterio |
|---|---|
| participantCode, runId, observerCode | Códigos separados de datos identificativos. |
| at, taskKey, start/end | Hora sincronizada y tarea, para enlazar con eventos. |
| actividad observada | lectura / exploración / respuesta / ayuda / interrupción externa / indeterminada. |
| evidencia | Descripción literal breve; no asignar ansiedad desde la latencia. |
| intervención | ninguna / aclaración de consigna / ayuda matemática / técnica / pausa. |
| autonomía | primer intento sin ayuda / reintento / asistencia / no observable. |
| contraste con sistema | coincidencia / falso apoyo / apoyo omitido / datos insuficientes. |
| salida | decisión del participante / decisión del responsable / final previsto / problema técnico. |

Mantener observación humana y autoinforme diferenciados. Revisar una muestra con dos observadores para conocer desacuerdos antes de usar etiquetas como referencia.

## Formas externas de ejemplo, pendientes de revisión docente

No están integradas al juego ni equivalidas psicométricamente. Emplean denominadores fuera del patrón principal para explorar generalización; esa diferencia también puede aumentar dificultad y debe revisarse. Alternar A/B entre participantes solo después de revisar su comparabilidad.

| Habilidad | Forma A | Solución A | Forma B | Solución B |
|---|---|---|---|---|
| Partes | De 5 partes iguales, se usan 2. ¿Qué fracción? | 2/5 | De 3 partes iguales, se usa 1. ¿Qué fracción? | 1/3 |
| Equivalencia | Expresa 2/5 en décimos. | 4/10 | Expresa 1/3 en sextos. | 2/6 |
| Suma igual | 2/5 + 1/5 | 3/5 | 1/3 + 1/3 | 2/3 |
| Resta igual | 4/5 - 1/5 | 3/5 | 2/3 - 1/3 | 1/3 |
| Suma distinta | Hay 1/2 litro y se añade 1/5 litro. ¿Total? | 7/10 litro | Hay 1/2 litro y se añade 1/3 litro. ¿Total? | 5/6 litro |
| Resta distinta | Hay 4/5 de metro y se corta 1/2 de metro. ¿Resto? | 3/10 metro | Hay 5/6 de metro y se corta 1/2 de metro. ¿Resto? | 1/3 metro |

Registrar por separado exactitud, explicación y ayuda; no sumar todo en una escala de ansiedad o capacidad. Separar datos usados para ajustar reglas y datos usados para evaluarlas. El tamaño de muestra y análisis de eficacia requieren diseño específico; estos ejemplos no lo reemplazan.
